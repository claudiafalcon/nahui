# Evidence Tiering

Three Nahui agents each run their own version of the same underlying discipline, under different tier names suited to their own domain:

- `knowledge-mentor` — Project Foundation / Learning Resources / General Knowledge (Model / External), checked strictly in that order.
- `brand-guardian` — Decision / Hypothesis / Validated / Aspiration, tagging every `/brand/` claim.
- Innovation-accounting / validation work (`marketing`) — Real / Proyectado / Calculado, tagging claims by whether they're observed, projected, or derived.

None of these tier definitions live here — they're genuine domain judgment and stay in the owning agent's own file. What's shared, and what this Skill exists to state once:

1. **Tag every claim individually by its exact origin tier.** A single answer or document often draws on more than one tier — tag each part, don't leave the whole artifact under one blended label.
2. **State which tier actually resolved the question**, when multiple were checked. Don't present a lower-tier answer alongside a higher-tier one as if they carried equal weight.
3. **Never blend tiers into a single unmarked claim.** If a conclusion draws on two tiers, say so explicitly rather than merging them into one voice.
4. **Never let a lower-authority tier read as more authoritative than it is** — a deliberate decision is not evidence; a curated secondary source is not a primary one; a projection is not a measurement. The tier tag itself is the guardrail against this, so don't drop it once a claim feels settled.
5. **Surface agreement and disagreement across tiers explicitly**, rather than silently resolving a conflict by picking one side.

The point of tiering is honesty about how much weight a claim can bear before someone acts on it — not procedure for its own sake.
