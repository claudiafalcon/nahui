# Demo Mode — Welcome Copy Restructure + "Reiniciar demo"

**New-Feature Workflow (D42), same feature family as `docs/passes/demo-mode-welcome.md`** — built against `product/02-ux/demo-mode.md`'s 2026-08-18 amendments (welcome-screen restructure §3.3; persistent Form-reminder banner §2.3/§3.6, restart §2.4/§3.7/§3.8), all through a complete review pipeline (`ux-critic`/`reviewer`/`brand-guardian`) and folded back into Approved before this pass started. Two pieces, both scoped strictly to `src/screens/DemoMode/`, `demoModeStorage.ts`, and one small, additive export in `store.tsx`.

## (1) `DemoWelcome.tsx` — §3.3 copy-only restructure

The old third bullet (fictitious business/products/customers) is folded into a new second intro sentence, which now also states the previously-missing fact that this is validation, not a sale. The bullet list narrows to exactly the two retention-critical, causally-ordered phone→OTP facts (unchanged since 2026-08-16). The closing sentence is fully rewritten to state plainly the questionnaire is part of the same activity, not a separate optional step, with the Product-Owner-requested softened reason clause ("nos ayuda a decidir," not "decide"). No JSX structure change beyond one new `<p className={styles.body}>` and removing the third `<li>` — `DemoWelcome.module.css` untouched, the existing `.body`/`.list`/`.listItem`/`.closing` classes already cover the new shape.

## (2) `ReminderBanner.tsx` — restart feature (§2.4/§3.7/§3.8), banner restructured to two rows (§3.6)

**Row structure.** `.banner` (a plain container, no longer itself the tappable element) now holds two children: `.row1` (the original full-width "Cuéntanos tu opinión — cuestionario" button, unchanged text/behavior/position) and a new `.row2` — a slim, visually darker (`--color-tezontle-dark`) line beneath it holding the passive "(8-12 min)" time estimate on the left and the "Reiniciar demo" control on the right. `.restartButton` deliberately uses `--text-meta` (11px) with an underline rather than `--text-label`'s filled-button treatment, so it reads as a minor utility control, never a second primary CTA — the spec's own explicit flag to `ui-designer` (§3.6). `--demo-banner-height` (the reserved space above `.app-shell`) increased from 40px to 66px to account for the second line.

**Restart mechanism.** New `restartDemo.ts` — clears `demoModeStorage.ts`'s device-acknowledgment key (new `clearDemoModeAcknowledgment()` export, parallel to the existing `acknowledgeDemoMode()`) and `store.tsx`'s own `AppState`-mirroring storage key, then calls `window.location.reload()`. Reuses `store.tsx`'s `STORAGE_KEY` directly — newly exported from that module (§8 item 8's own flag: avoid a second hardcoded copy of the same string literal that could silently drift). Neither clear call reads or interprets its key's value — `localStorage.removeItem` is the entire operation, preserving the spec's "no domain read" posture. `window.location.reload()` is the chosen mechanism, not `store.tsx`'s existing `resetPrototype()`, per the spec's own reasoning (confirmed again by direct inspection this pass): `StoreProvider` mounts above `DemoModeGate` in `main.tsx`, so an in-app-only state transition would never remount `DemoModeGateActive`'s own local `gate` state.

**Confirm dialog (§3.7).** Reuses the existing `Sheet` component — the same dimmed-backdrop convention `Selling.tsx`'s "¿Ya terminaste por hoy?" and `SettingsScreen.tsx`'s "¿Cerrar tu sesión?" dialogs already use — with local `confirmTitle`/`confirmBody`/`confirmRow` classes copied verbatim (same token values) into `ReminderBanner.module.css`, since neither of those two screens' own CSS modules is a natural import target for this component. Wrapped in a new `.confirmLayer` (`position: relative; z-index: 600`) so the dialog paints above the banner's own `z-index: 500` — both the banner and this dialog deliberately render at the true viewport, outside `AppRouter`'s own `app-shell` device-frame containment (unlike every other `Sheet` consumer in this codebase), because the dialog needs to dim the banner too, not just the screen beneath it.

**Defensive fallback (§3.8).** New `RestartFailed.tsx`, reusing the identical `ColdStart.module.css` wrap/copy/cta shape `DemoLoadError.tsx` (§3.5) already uses — same class of failure, same "Reintentar." `ReminderBanner` renders it as a full replacement of its own output (own `app-shell` wrapper, since nothing here is otherwise nested inside `AppRouter`'s) when `restartDemo()` throws; tapping "Reintentar" simply re-invokes the same clear-and-reload attempt.

**Receipt-screen exception (§2.3 check 2, `home.md §3.8f`) inherited automatically** — both rows live inside the same `{!receiptActive && (...)}` guard the single-row version already had; no new exception logic was needed or added.
